# Как устроена «Буквица»

Expo SDK 57 / React Native 0.86 / TypeScript, Android, портрет. Сервера и сети нет (ADR студии 0005). Стек и
общие правила — устав ([ADR 0003](https://github.com/Nefeste/gornitsa/blob/main/adr/0003-expo-stack-ci.md),
[`05-rules.md`](https://github.com/Nefeste/gornitsa/blob/main/docs/05-rules.md)).

## 1. Слои

```
content/ (YAML + скачанный Даль) ──tools/content/build.ts──▶ src/content/generated/bundle.ts
                                                                      │
src/engine/  чистый движок: задачи, ход решения, календарь ◀──────────┤
src/state/   состояние приложения, итоги, настройки, хранение, дата   │
src/screens/ восемь экранов ◀─────────────────────────────────────────┘
src/ui/      токены студии, шрифты, кнопка, карточка, кружки, буквица
src/i18n/    все строки для игрока
```

- **`src/engine/`** — без React, `Date`, `Math.random` (устав, «Код»). Дата приходит строкой «ГГГГ-ММ-ДД»;
  случайность (порядок плиток и вариантов) — из хеша идентификатора задачи, поэтому у всех игроков одна и та же
  задача выглядит одинаково. `tasks.ts` — задача из пословицы и проверка ответа; `play.ts` — ход решения: состояние →
  состояние (касание плитки, подсказка, «Показать ответ»); `day.ts` — календарь и строка итога; `letters.ts` — алфавит
  (единственный файл движка с кириллицей).
- **`src/state/`** — `game.ts` (экран, итоги, настройки, сегодняшняя дата), `progress.ts` и `settings.ts` (чистый
  разбор сохранённого), `storage.ts` (AsyncStorage: `bukvitsa.results.v1`, `bukvitsa.settings.v1`), `today.ts`
  (дата телефона; в веб-сборке — `?date=` для сценария).
- **`src/screens/`** — экраны переключаются состоянием (`App.tsx`), без роутера: их восемь, и они простые. Экран
  задачи держит `Play` и отдаёт итог в `game.record`, когда задача решена впервые.
- **Содержание** — в сборке целиком (около 300 КБ JSON). Новые тетради и дни календаря приходят с обновлением игры.

## 3. Сохранение

- Итоги: `{ [id задачи]: { done, hints, mistakes, shown } }` — разбор отбрасывает битое по записи
  (`parseResults`). Номера задач вечные, поэтому итоги переживают любое обновление.
- Автобэкап Android выключен (`allowBackup: false`), как у «Наготове»: прогресс живёт на телефоне.

## 4. Графика (ADR 0023 устава)

Правила — устав: [«Графика»](https://github.com/Nefeste/gornitsa/blob/main/docs/05-rules.md#графика),
[ADR 0023](https://github.com/Nefeste/gornitsa/blob/main/adr/0023-graphics.md). Здесь — как «Буквица» их выполняет.

1. **Цель кадра — на целевом телефоне студии** (телефон владельца: современный Android, экран 120 Гц; модель — в
   управе, `uprava#74`): 60 кадров по медиане, кадров дольше 25 мс — не больше 1 %. Анимированной сцены нет —
   экран меняется по касанию. Бюджет — [спецификация, «Бюджет»](specs/2026-11-v1.md#8-бюджет). **Не сделано:** замер
   на телефоне — делает владелец.
2. **Лист стиля** — [`13-art.md`](13-art.md); три эталонных кадра предложены агентом, ждут одобрения владельца в PR
   (`uprava#76`).
3. **Модели и спрайты из скриптов** — их нет: буквица, кружки, плитки рисуются кодом (`react-native-svg`, `View`).
   Растровых картинок в игре нет; иконка — скриптом с паспортом (к 1.0).
4. **Одна палитра из токенов** — только токены брендбука студии (`src/ui/theme.ts`, копия `brand/tokens.css`):
   лён, бумага, чернила, кумач, ель, лён-нить. Своих цветов нет.
5. **Снимки и замер** — сценарий в браузере снимает ключевые экраны в `tools/e2e/out/`; PR с графикой прикладывает
   «до — после».
6. **Отклик — на касание игрока**; «Меньше движения» — в настройках (как в телефоне / вкл / выкл). В 0.1 анимаций
   нет вовсе; тест следит, чтобы любая будущая анимация читала `useLessMotion()`. Вибрации нет.
