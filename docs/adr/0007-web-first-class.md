# 0007. Веб-сборка — равноправная цель с первого дня: проверки, закрытый тест и Яндекс Игры

**Решили.**

- Веб-сборка Expo (`npx expo export --platform web`) собирается с 0.1 и всегда зелёная:
  сценарий Playwright на ней — обязательная проверка перед push (`06-testing.md`, §5),
  закрытая проверка на сайте (`gornitsa.games/bukvitsa/test/`, по образцу «Узоров») —
  с 0.2.
- **Ничего только-нативного в ядре**: покупка, реклама, звук, вибрация — за адаптерами
  с веб-заглушками; графика — SVG ([0004](0004-expo-no-skia.md)); хранилище — за
  интерфейсом с веб-реализацией (localStorage/IndexedDB на вебе, файл на телефоне).
- **Яндекс Игры** — вторая площадка той же сборки с SDK площадки (1.2): её реклама
  и покупки подключаются теми же адаптерами.

**Почему.**

- Веб-сборка — самый дешёвый способ проверять игру руками и сценарием: без телефона,
  без APK, в CI. Соседи пришли к этому не сразу и переделывали; «Буквица» начинает
  с этого.
- Яндекс Игры — 50 млн игроков в месяц [в] без установки и без магазина; словесные игры
  там — массовый жанр. Для игры без сервера вторая площадка почти бесплатна, если
  сборка с первого дня — веб.
- Закрытый тест в браузере под паролем — единственный способ показать игру владельцу
  и тестерам до выпуска без установки APK.

**Платим.**

- Каждая новая возможность делается дважды мысленно: «а как это на вебе?»; адаптер
  и заглушка — лишний файл.
- Веб-хранилище хуже телефонного: нет автобэкапа, очистка данных браузера стирает
  прогресс. На Яндекс Играх это закрывает их SDK сохранений (1.2); для закрытого теста
  принято.
- Сценарий Playwright — минуты CI на каждом PR с кодом.

**Когда пересмотреть.** Если Яндекс Игры к 1.2 окажутся закрыты для нашей модели
(условия оферты) — веб остаётся как проверка и закрытый тест, площадка — вопрос.
