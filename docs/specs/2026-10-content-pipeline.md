# Сборка контента: записи, проверки, календарь

**Версия:** 0.1–0.3 **Состояние:** задумано

## Зачем

Задачи — это второй поток работы, и он должен идти без программиста: ассистент пишет
записи по источнику, сборка проверяет их и собирает в набор, «виртуальный игрок» ловит
двусмысленность, владелец сверяет и ставит `checked`. Правила — [`../09-content.md`](../09-content.md);
здесь — что делают команды и как принимаем.

## Проверка по обещаниям

Седьмой вопрос устава («происхождение, которое не можем назвать») — именно то, что
сборка не пропускает: запись без источника, раздела/страницы и основания — ошибка.

## Команды

| Команда | Что |
|---|---|
| `bun tools/content/build.ts [--check] [--release]` | `content/` → `src/content/generated/pack.ts`; проверки §5; отчёт `dist/report.md`; `--release` берёт только `checked` |
| `bun tools/content/play.ts` | «виртуальный игрок»: двусмысленные ряды (второе слово из ряда по частотному словарю), варианты, части |
| `bun tools/content/calendar.ts --from ГГГГ-ММ-ДД --years N` | дописывает `content/calendar.yaml` с чередованием видов; выпущенные даты не трогает |
| `bun tools/content/release.ts vX.Y.Z` | пополняет `content/released.json` версиями записей, вошедших в выпуск |

Генератор лишних букв и перемешивания — `tools/content/shuffle.ts`: xorshift от
`sha256(id + ':' + version)`; тест держит золотые ряды для записей-образцов.

Частотный словарь для «виртуального игрока» — нужен список русских слов с правом
на использование: кандидат — словарь форм из открытого корпуса (OpenCorpora, CC BY-SA —
**сверить**, годится ли лицензия для инструмента, который в игру не попадает; в игру
словарь не входит, только в проверку). До решения — проверка по самим ответам набора.

## Что увидит игрок

Ничего напрямую; результат — задачи в игре без ошибок и без двусмысленных рядов.

## Данные

`content/<вид>/<номер>.yaml`, `content/notebooks.yaml`, `content/calendar.yaml`,
`content/released.json`, `content/stoplist.txt` — форматы в
[`../09-content.md`](../09-content.md), §3–4. Выход — `src/content/generated/pack.ts`
(не в git).

## Неудачные случаи

- Запись не проходит проверку — сборка красная с именем файла и правилом; в CI —
  в сводке шага.
- Календарь кончается раньше, чем через 365 дней от сегодня, — сборка с `--release`
  красная.
- Дата календаря ссылается на запись не `checked` — красная с `--release`.
- Дубликат текста (две записи с одной пословицей) — предупреждение; с одним ответом
  в одной тетради — ошибка.

## Критерии приёмки

- Две записи-образца из этапа 0 собираются; `pack.ts` детерминирован байт в байт.
- Все правила §5 покрыты тестами на нарочно сломанных записях
  (`tools/test/fixtures/content-bad/`).
- Отчёт `dist/report.md` показывает число записей по видам, тетрадям, статусам и длину
  календаря.
- К 0.3: первая тетрадь — 40 `checked`; к 1.0 — восемь тетрадей и ≥ 365 дней.

## Чего здесь нет

Загрузки наборов по сети, редактора записей, автоматического отбора пословиц из
Викитеки (ассистент читает раздел и выбирает руками по §2 и §8).
