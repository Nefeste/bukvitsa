# Как ведётся работа

Общий порядок — в уставе ([`docs/04-process.md`](https://github.com/Nefeste/gornitsa/blob/main/docs/04-process.md)
в `Nefeste/gornitsa`): документы в репозитории, «сначала спецификация, потом код», ADR,
версии, ветки и CI, выпуск. Здесь — только особенности «Буквицы».

## Два потока работы

1. **Возможности** — спецификация в [`specs/`](specs/) до кода, код и тесты, правка
   документов и дорожной карты в том же PR.
2. **Задачи (контент)** — записями в `content/` по [`09-content.md`](09-content.md):
   сборка проверяет, «виртуальный игрок» ищет двусмысленность, человек ставит
   `review: checked` после сверки со сканом. Новая тетрадь — это PR с записями, строкой
   в `content/notebooks.yaml`, отчётом сборки в описании и, если тетрадь входит
   в версию, разделом версии в `README.md`.

## Версии

- Правило трёх чисел — по уставу. До магазина — `0.x`; первый выход в RuStore — `1.0.0`.
- Номер версии живёт в `app.json` (`version`, `android.versionCode`), `package.json`,
  `package-lock.json` и на экране «Об игре» (строка в `src/i18n/`); тест
  `tools/test/version.test.ts` сверяет их. `versionCode` — +1 на каждую сборку, ушедшую
  в магазин.
- Каждой версии — раздел в корневом [`README.md`](../README.md): что изменилось для
  игрока. Тот же текст короче — в «Что нового» RuStore (`store/listing.ru.md`).
- Выпуск версии добавляет выпущенные записи в `content/released.json` (`id → version`):
  с этого момента текст записи меняется только новой `version`, а календарь — не меняется
  вовсе (ADR [0002](adr/0002-daily-calendar-offline.md)).

## Ветки

- `main` — всегда то, что можно выпустить; работа — в ветках `claude/<задача>`, в `main` —
  через PR.
- **Проверки на PR** (`.github/workflows/pr.yml`, ADR студии 0019): типы, линтер, тесты,
  сборка контента с проверками. Пока кода нет, задача отвечает «зелёным» сразу; PR только
  с документами пропускает шаги внутри задачи.
- **Автослияние** (`automerge.yml` + `.github/scripts/automerge.ts`, ADR студии 0018):
  PR без путей владельца сливается сам при зелёных проверках и метке `ревью: ок` от
  Ревьюера из другой сессии. Пути владельца — `.github/CODEOWNERS`: `deploy/`, `.github/`,
  `server/`, `src/money/`, анкеты и политика, `app.json`, `plugins/`,
  `content/calendar.yaml`. Что нужно включить в настройках репозитория — «Ждёт владельца»
  в [`../STATUS.md`](../STATUS.md).
- Перед каждым push агент сам прогоняет то, что прогонит CI (команды — в
  [`../AGENTS.md`](../AGENTS.md)), а для изменений интерфейса — веб-сборку и сценарий
  в браузере.

## Автоматика

| Workflow | Когда | Что |
|---|---|---|
| `pr.yml` (с 0.1) | PR в `main` | сборка контента, типы, линтер, тесты (проверка «Типы, линтер, тесты») |
| `automerge.yml` (с 0.1, из набора `gornitsa-kit`, ADR студии 0022) | метка `ревью: ок`, новый коммит, конец проверок | сливает PR по правилам ADR 0018 |
| `android.yml` (с 0.1, ключ, подпись и проверки APK — из `gornitsa-kit`) | тег `vX.Y.Z` | APK, подпись постоянным ключом, выпуск в Releases; `--release`-контент — с 0.2; AAB не собирается, пока нет Google Play |
| `site.yml` (копия из «Узоров», с 08.11.2026) | в 04:41 по Москве, если `main` ушёл вперёд; вручную (Actions → «Веб-версия для сайта») | сборка с `BUKVITSA_WEB_BASE=/bukvitsa/test` → сценарий `tools/e2e/browser.ts` под этим адресом и с CSP сайта → шифрование открытым ключом машины (`https://gornitsa.games/.well-known/bukvitsa-age.pub`) → ветка `vps` (один коммит, два файла) → машина забирает её сама (`deploy/bukvitsa` в `Nefeste/gornitsagames`) → `gornitsa.games/bukvitsa/test/` под паролем. Пока ключа на сайте нет — предупреждение, ничего не выкладывается |
| `rustore.yml` (с 0.1, из `gornitsa-kit`) | вручную | APK из Releases → черновик версии в RuStore |

Минуты Actions общие на закрытые репозитории владельца — 2000 в месяц; проверки на PR
«Буквицы» без контента — около 3 минут (оценка, сверить по первым запускам).

## Секреты и переменные репозитория

Заводит владелец; агентам значения не выдаются и не нужны:

| Секрет | Для чего | Когда |
|---|---|---|
| `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` | подпись APK постоянным ключом (ADR студии 0006) | к 0.2, первой сборке на телефон |
| `RUSTORE_KEY_ID`, `RUSTORE_PRIVATE_KEY` | загрузка в RuStore (`rustore.yml`) | к 1.0 |
| идентификаторы рекламных блоков | в `app.json`/конфиге плагина — это не секреты, но ставит владелец вместе с аккаунтом сети | к 0.5 |

Ключ подписи заводится **один раз** по инструкции «Узоров» (`docs/05-process.md`, «Как
завести ключ подписи») и не меняется никогда.

## Выпуск версии — чек-лист

Общая часть — в уставе; шаги «Буквицы»:

1. `bun tools/content/build.ts --check --release` зелёный; «виртуальный игрок» без
   ошибок; длина календаря от сегодня — не меньше 365 дней.
2. Все задачи календаря и тетрадей версии — `review: checked`; `content/released.json`
   пополнен.
3. Номер версии поднят во всех местах; раздел версии в `README.md`; «Что нового»
   в `store/listing.ru.md`.
4. `store/site/page.ru.md` соответствует версии (статус, снимки, цена); снимки
   пересняты скриптом, если менялись экраны.
5. Если менялось, что игра собирает или отправляет (рекламный SDK, разрешения), —
   раздел игры в политике на сайте поправлен **до** выпуска.
6. Тег `vX.Y.Z` → `android.yml` → владелец проверяет APK на телефоне → `rustore.yml` →
   владелец публикует в RuStore.
7. После публикации — строка в дорожной карте, запись в журнале, новость на сайте,
   если версия заметная.

## Отзывы в RuStore

Читаются раз в неделю; повторяющаяся жалоба — задача в дорожной карте. Ответы — черновиком
через «Сени», публикует владелец (ADR студии 0013). Жалоба на конкретную задачу
(«ответ неверный», «так не говорят») — проверка по источнику и, если мы ошиблись,
новая `version` записи в ближайшей версии игры.
